# Badge catalogue managed by the board

Objective: the board creates, edits, archives and deletes badges, and awards them to members, without migrations or deploys.
Branch: `feat/badge-catalogue` (from `develop`). Delivery: `ask-on-risk`, chain `feature-branch-chain` (user, 2026-11-03: "Todo en la rama, al final"): one work-unit commit per task on this branch, merged into `develop` when T1-T3 are done. Test runner: Vitest (`npm run test:unit`, `npm run test:integration` with local Supabase), Playwright for UI.

## Specs

- **S1 Catalogue in the database.** User: "seria requerido hacer que los admins pudieramos crear nuevas, eliminar y gestionarlas en los usuarios." A table `public.badges` replaces the hard-coded list (`member_badges` CHECK, `admin_badge_keys()`, `STORED_KEYS`, `BADGE_ORDER`, `KNOWN_BADGE_KEYS`, audit `BADGES`, `ICONS`, i18n `badge_*`). Columns: `key` (immutable slug, primary key), `name`, `earned_text`, `locked_text` (`{ca, es, en}`, `ca` required, the others fall back to `ca`), `icon` (one of a closed list of `react-icons/md` icons, no uploads), `sort_order`, `show_locked`, `archived_at`/`archived_by`, `created_by`, `created_at`, `updated_at`. `member_badges.badge_key` becomes a foreign key to it (the existing rows already use valid keys: no data migration). The two current badges are seeded with today's texts. Members read the catalogue except archived badges; API roles cannot write it.
- **S2 Board functions.** SECURITY DEFINER `admin_*` functions called with the session client, one audit entry per change: list (with holder counts), create, update (the key never changes), archive, restore. Delete is superadmin-only and only for a badge that was never awarded ("Borrar de verdad: solo superadmin, y solo si nunca se ha concedido").
- **S3 Archiving.** User, asked whether holders keep an archived badge: "Desaparecen para todos". An archived badge is hidden from every member (earned or locked) but its `member_badges` rows are kept, so restoring it is lossless. It cannot be awarded or revoked (`admin:badge_archived`). The member file shows it greyed as "Arxivada". The member data export (A-11) and the register (S-4) still include it.
- **S4 Awarding.** `admin_award_badge` / `admin_revoke_badge` validate against the non-archived catalogue. A bulk award gives one badge to several active members at once, one audit entry per member, skipping members who already hold it.
- **S5 Audit snapshot.** Every badge audit entry stores the Catalan name at that moment, so the activity log stays readable after a rename or a delete. New actions `badge.create`, `badge.update`, `badge.archive`, `badge.restore`, `badge.delete` (no target member), all inside the existing `badge.*` filter group.
- **S6 App reads the catalogue.** Member home, member file and activity log read names, texts, icons and order from the catalogue; nothing visible changes for members after the switch.
- **S7 Admin UI.** A new admin tab "Insígnies": catalogue with holder counts, create and archive; one page per badge to edit texts and icon (with a preview), see holders and bulk-award. The archive dialog says how many members stop seeing it ("N socis la deixaran de veure"). User approved the mockup as drawn: "Tod ok con el diseño". The mockup (private artifact https://claude.ai/artifact/8xU27WmGcutM1cQpE6EJwv; local copy `/tmp/claude-1000/-home-best4up-dev-personal-darkstone-darkstone-cat/00329e36-efa6-4e22-b4d2-6c187facdab0/scratchpad/badges-mockup/index.html`) is the reference for layout and Catalan copy:
  - **S7.1 Tab.** "Insígnies" (`/admin/badges`), visible to every board member, between "Activitat" and "Procediments" (7 tabs with "Rols" for superadmins).
  - **S7.2 Catalogue `/admin/badges`.** Card "Insígnies actives" with button "Nova insígnia"; first row "X anys amb Darkstone" marked "Automàtica" (not editable, no actions); then each active badge in `sort_order` with icon circle, name (link to its page), earned text, holders count ("12 socis"), "Visible bloquejada" or chip "Oculta fins que s'aconsegueix", languages present ("ca · es · en" / "Només ca"); actions "Gestiona" and "Arxiva". Card "Arxivades" (greyed rows, "N socis la tenien", "Arxivada el <date> per <name>" if available) with "Restaura" and "Esborra" (superadmin only, disabled with the reason when `ever_awarded`; hint text as in the mockup). Side card "Com funcionen" (Atorgar / Arxivar / Esborrar + notice about the activity log).
  - **S7.3 Badge page `/admin/badges/<key>`.** Back button "Insígnies"; edit card with the key shown read-only ("Clau: …"), language tabs Català / Castellano / English (an orange dot marks a language without text), fields Nom (60) / Text quan la té (200) / Text quan encara no la té (200), Catalan required, icon picker (the 16 icons, `aria-pressed`), switch "Mostra-la bloquejada a qui no la té", field "Ordre", buttons "Descarta els canvis" / "Desa" (sends only changed fields through `admin_update_badge`). Preview card "Com la veu el soci" (earned + locked, following the selected language tab). Card "Socis que la tenen" (active holders with name link to the member file, number, award date, "Retira" opening the existing revoke dialog with optional reason; "Mostra'n N més" after 10; former members listed apart without a button) and button "Atorga a socis". An archived badge's page is read-only apart from "Restaura". Unknown key → 404.
  - **S7.4 Dialog "Nova insígnia".** Fields Nom en català, Clau (proposed from the name: lower case, digits and "_", editable until created; hint "No es pot canviar després"), Text quan la té, Text quan encara no la té; buttons "Cancel·la" / "Crea i obre" (creates with icon "star" and opens the badge page).
  - **S7.5 Dialog "Atorga a socis".** Search active members by name or number, checkbox list (members who already hold it are disabled, "ja la té"), selected chips, "N seleccionats · màxim 100", optional note (hint "No escriguis DNI ni telèfons"), confirm "Atorga a N socis" → `admin_award_badge_bulk`; result notice "Atorgada a N socis" (+ "M ja la tenien").
  - **S7.6 Dialog "Arxiva la insígnia".** Big number of active holders + "socis actius la deixaran de veure al seu perfil." + warning notice; confirm "Arxiva" (danger). "Restaura" and "Esborra" also confirm in an `AdminDialog`.
  - **S7.7 Activity log.** `badge.create`, `badge.update`, `badge.archive`, `badge.restore`, `badge.delete` render with the stored name (no target member); `audit:sensitive_details` on a badge text gets a clear message.
  - All copy in ca/es/en; admin pages `noindex`, not in the sitemap; board guard from the admin layout; data only through the `admin_*` functions with the session client.
- **S8 Tenure badge (done).** User: "Deberia ser automatica, contando desde la fecha de la actual alta, por cada año que pase cambiar la insignea a \"X años con Darkstone\", y que solo sea una que va cambiando de nombre." and "Sustituye" (it replaces "Membre {year}"). Derived in code, never in the catalogue.
- Out of scope (user: "estas insigneas las dejamos descartadas"): badges for sessions attended or plays, because the Ludoya public API has no attendees.
